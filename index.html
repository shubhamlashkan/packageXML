HELP & GUIDANCE

Frequently asked questions

Quick answers for creating and using Salesforce metadata manifests.

What if I can’t find a metadata type?

You can add a metadata type entry to the XML after generation. Use the exact API name documented by Salesforce’s Metadata API and follow the structure of the other <types> entries. Confirm that the type is supported by your selected API version.

Which API version should I select?

Use the version your project or deployment workflow targets. If your project has an sfdx-project.json file, its sourceApiVersion is a useful reference. Older versions may not support newer metadata features.

Does this website connect to my Salesforce org?

No sign-in or org authorization is required. Your selections and XML are processed in your browser and are not sent to a Salesforce org by this tool.

Does validation guarantee deployment will succeed?

No. Local checks can catch common issues, but cannot confirm component existence, org permissions, dependencies, or all Salesforce deployment rules.

What is a destructive changes manifest?

It identifies metadata to delete rather than retrieve or deploy. Deletion workflows have additional deployment requirements; review Salesforce’s current deployment documentation and carefully inspect every member before use.

What does the ZIP download contain?

Package mode includes package.xml. Destructive changes mode includes package.xml and destructiveChanges.xml using the selected API version.

Why is a component missing from the XML?

Only selected metadata types with component names are included. Check that the correct type is selected and that names are entered in its matching field.

Is my XML uploaded or stored?

Manifest generation and ZIP creation run locally in your browser. This tool does not upload your manifest to a backend. Your organization may still have policies about accessing unapproved websites.

Can I import an existing package.xml?

Yes. Use Import & Merge to choose an existing package.xml. The tool previews the imported members and merges them with your current selections after you confirm.

Will importing a package.xml create duplicate members?

No duplicate type/member entries are added. If the same member is already selected or appears more than once in the imported manifest, the merged output keeps one entry.

What happens to metadata types this generator doesn't display?

The importer reports unsupported types. The tool is designed to preserve valid imported entries in the generated manifest where possible; review the import summary before applying the merge.
