Deployment Safeguard: Metadata retrievals may omit implicit standard defaults or system-managed mappings. Validate changes in a sandbox or deployment dry run before production deployment.

HELP & GUIDANCE

Salesforce Permission Diff FAQs

Important details about supported files, permission comparisons, and audit limitations.

Can I compare a Salesforce Profile with a Permission Set?

No. Compare two Profile XML files with each other, or compare two Permission Set XML files with each other. The tool does not support comparing a Profile directly with a Permission Set.

What permission changes can the checker identify?

It compares supported settings explicitly present in the uploaded Metadata API XML, including object permissions, field-level security, system permissions, Apex class access, Visualforce page access, flows, tab visibility, record types, and other supported declarations.

Does it calculate a user's effective Salesforce access?

No. It compares the settings declared in the two files. Effective access can depend on assignments, licenses, hierarchy, sharing, permission set groups, muting, and other org configuration that is outside a two-file metadata diff.

Are missing XML entries treated as disabled?

No. Missing entries are treated as not specified, not automatically as false. Profile metadata may omit settings that were not included in the retrieval.

Are my Salesforce metadata files uploaded?

No. File reading and comparison run locally in your browser. The tool does not send the XML contents to a server.

Can I export the permission comparison?

Yes. Use Export Diff to CSV to download the comparison results. The export respects the filters currently applied to the results.

Does a permission diff guarantee a safe deployment?

No. Use the comparison as a review aid, then validate changes in a sandbox or deployment dry run. Metadata retrievals may omit implicit defaults or settings not included in the source files.
